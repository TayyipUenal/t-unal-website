# Video, audit pages and inquiry forms

## Build

Run `npm ci`, `npm run build`, and `npm run lint`. The build pre-renders six complete HTML pages and writes per-page titles, descriptions, canonical URLs, Open Graph/Twitter metadata, JSON-LD, sitemap.xml and robots.txt. Production requires Apache with PHP 8.1 or newer; no Node process or database is needed.

## Routes

- `/`
- `/audits/iso-9001/`
- `/audits/iso-14001/`
- `/audits/iso-45001/`
- `/impressum/`
- `/datenschutz/`

The canonical site is `https://tayyipuenal.de`. Apache redirects www.de to the canonical hostname. Each audit page has descriptive internal links, section chips, breadcrumbs, related audit pages and its own form.

## Hero media

`public/media/workflow-de.mp4` is a 24-second, 1280×720, 25 fps H.264 motion-graphics video with German on-screen copy. It is intentionally silent and readable without sound. It includes a poster, German captions and a text transcript. The player pauses when out of view and respects reduced-motion settings.

The video is a schematic process explanation, not a recording of a live document-processing application. Regenerate it with `npm run video` using Node, @napi-rs/canvas and ffmpeg. The script uses local Arial fonts on macOS and the supplied unmodified logo as a drawing asset.

## Inquiry delivery

`public/api/inquiry.php` accepts JSON POST requests from the site's allowed origins and forwards them only to `info@tayyipuenal.de`. The fixed envelope/From sender is the same domain mailbox; the visitor address is used only as Reply-To. No mail password or API secret is stored in the frontend.

The endpoint validates fields, rejects header injection and honeypot submissions, caps request size and limits each IP to five attempts per hour and the endpoint to 100 attempts per hour. It stores hashed IPs, fingerprints, request IDs and mail acceptance status in a locked temporary file outside the document root. Entries expire after an hour and are pruned on the next submission. Form text itself is not written to that file. The request ID prevents duplicate mail when a successful submission is retried after a connection interruption.

Success is shown only when PHP's mail function accepts the message for delivery. Final mailbox receipt must be checked separately; mail acceptance is not a delivery receipt.

For local backend verification, use the official PHP CLI image with `sendmail_path=/bin/true` and the public directory mounted read-only, serving only on 127.0.0.1:8086. `node scripts/test-inquiry.mjs` tests method/origin validation, malformed input, header injection, honeypot, request size, success, idempotency, changed-request conflict and rate limiting without sending email.
